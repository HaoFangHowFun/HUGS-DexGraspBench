# Sharpa Phase 1: collision and contact validation

Full results: `sharpa_validation.json`. Measured summary: `sharpa_phase1_results.md`.
This suite validates model behavior over a defined motion/contact envelope, not
free-object grasp retention or hardware behavior.

## Reproduce

Keep `HUGS-Sharpa-Assets` beside this repository. The two extra geometry dependencies
are pinned in `scripts/requirements-sharpa-validation.txt`. With those installed in
the Bench environment, run:

```bash
.venv/bin/python scripts/prepare_sharpa_collision.py
.venv/bin/python scripts/build_sharpa_models.py
.venv/bin/python scripts/validate_sharpa_phase1.py
```

Preparation is needed only to rebuild the provided derived parts. Otherwise run
only the final command. The runner writes diagnostics and exits nonzero when an
acceptance check fails. `validate_sharpa_models.py` remains a smaller FK/hold check;
it now writes `sharpa_model_validation.json` without overwriting the full report.
Historical results remain in `sharpa_phase0_validation.json`.

## Geometry and collision policy

The original palm STL is concave. A single MuJoCo mesh collider fills its recesses
with a convex hull. At canonical zero, source-triangle intersection checks show no
solid overlap for palm/thumb MC, palm/index MCP, palm/ring MCP or palm/pinky MC,
while the single hulls intersect. Bench now represents each palm with 64 convex
parts generated by V-HACD. Source/part hashes, parameters, and missing/added union
volume are recorded in `assets/hand/sharpa_wave/collision/manifest.json`.

Only the Bench palm collision representation changes. Original visual meshes,
URDFs, link transforms, axes, joint order/limits, explicit masses/inertias, and all
other collision meshes are preserved. An initial 32-part experiment still had a
false contact near right `thumb_CMC_AA=0.087275 rad`; the finer version removes that
sampled artifact without disabling the body pair.

**There are no new self-collision exclusions.** Excluding the whole palm/thumb pair
would be unjustified: near thumb CMC flexion/extension limits, the source collision
geometry itself intersects. Inter-finger contacts during deep closing/lateral
motion are also genuine. The positive-control deep-closing test verifies that these
contacts still impede motion rather than silently passing through other fingers.

Automatic parent filtering also matters. Fixed palm ancestors belong to the world
weld group in the original fixed-root model. Attaching the hand to the free mocap
root changes the effective welded groups. The report includes the parent/weld-group
table, original fixed-root contacts, original attached contacts and final attached
contacts. This explains why the original static model reported four zero-pose
contacts while the original Bench attachment reported only palm/thumb MC. No global
parent-filter or collision-mask flags are disabled.

Diagnostics use independent URDF FK and double-precision Manifold solids with
explicit error checks. An invalid solid is never counted as an empty intersection.
Some source STL files have tiny open seams/holes. Diagnostic copies receive small
triangle/quad hole closures, or convex closure only for nearly convex open meshes
with negligible volume change. Every repair and volume change is recorded; source
meshes are not overwritten. These are numerical geometry checks, not proof of
physical CAD clearance at arbitrarily small scales.

The static scan records the deepest sampled occurrence of every distinct contact
pair, plus every sampled palm-contact occurrence. This avoids hiding a shallow palm
approximation contact behind a deeper genuine contact of the same pair. Source,
original-hull and final-proxy overlap volumes are reported separately.

## Simulation settings compared with Shadow

| Setting | Existing Shadow / shared MjHO | Sharpa |
| --- | --- | --- |
| Step / integrator | 0.004 s / implicitfast | Same shared MjHO path |
| Gravity in evaluation scene | Disabled | Disabled |
| Contact solref / first three solimp values | `[0.005,1]` / `[0.5,0.99,0.0001]` | Same MjHO override |
| Contact settings | Elliptic cone, impratio 10, noslip 2, condim 4 | Same; test friction `[0.5,0.01]` |
| Position control | kp 5 in Shadow defaults | kp 2, kv 0.05 |
| Joint damping / frictionloss | 0.05 / 0.01 in Shadow defaults | Source defaults retained; actuator kv supplies damping |
| Armature | 0.0002 | 0.00001 numerical regularization |
| Soft joint limits | Shadow defaults | solref `[0.008,1]`, solimp `[0.99,0.999,0.0001,0.5,2]` |
| Actuation | Includes finger tendon coupling | 22 independent joints, source effort bounds |

Effective compiled settings are recorded in JSON. The small armature addresses
limit overshoot under inter-finger pressure with very small distal-link inertias.
The initial stress test exceeded a DIP lower limit by about 0.0063 rad without a
numerical warning. No joint range was enlarged to accommodate this; the final
measured violation is in the results summary. These are simulation parameters,
not measured hardware calibration. All changes remain in HUGS-DexGraspBench.

## Test coverage and interpretation

- Both hands: canonical joint order, limits, FK, visual/non-palm collision geometry,
  explicit masses/inertias, actuator mapping and bounds.
- Canonical-zero and temporary -10-degree hold checks. The offset is used only by
  the historical hold regression, never as a URDF zero or Phase 1 motion reference.
- Ten motions per hand: zero, thumb opposition, four finger flexions, extension,
  abduction, partial combined closing and pinky cupping. Each uses a 2-second cosine
  ramp, 1-second hold, then the same return to canonical zero.
- Static full-range scan: nine values per joint, 198 configurations per hand.
  Limits alone do not imply that a pose is collision-free.
- All 44 single-joint lower/upper-bound commands per hand, distinguishing tracked
  commands from self-contact-limited commands. Soft-limit violation and warnings
  are checked even when contact prevents tracking.
- Out-of-range index-PIP commands at both ends check control clipping and limits.
  A separate deep-closing probe must retain real inter-finger contact.
- Thirty object tests: each of five pads, both hands, box/sphere/cylinder objects
  approximately 16 mm across. A compliant six-axis fixture presses a free object
  0.5 mm into its initial shallow pad contact for 2 seconds, then releases it for
  0.5 seconds. No object weld is used. Contact points/normals, penetration, forces,
  joint errors, object speeds, fixture gains/target, and warnings are recorded.

The initial unrestricted constant-force probe could push a free object off a pad
and then accelerate it indefinitely. That is not a useful stability/grasp-success
test. The final fixture tests separate controlled contact response from unforced
release and do not claim that the hand retains a free object.

## Acceptance and remaining gates

Thresholds are in `config/sharpa_validation.yaml`: 0.05 rad peak and 0.001 rad settled
tracking error; 0.005 rad maximum joint-limit violation; 1 mm maximum contact
penetration; at least 95% late-hold contact persistence; 1 mm/s final held-object
speed; 5 cm/s released-object speed; no numerical warnings. Real contact-limited
boundary commands are classified separately from unexplained tracking failures.

Passing supports controlled single-hand grasp-evaluation experiments in the tested
envelope. It does not certify all joint combinations, sub-decomposition-scale
clearances, physical friction/gains, object retention, gravity/load disturbances,
floor interaction, learned-result conversion or dual-hand grasps. The report keeps
`full_grasp_evaluation_ready=false` until those remaining gates are checked.

The existing Shadow source/configuration and evaluation pipeline are unchanged.
No synthesis, training or hardware commands are part of the tests.
